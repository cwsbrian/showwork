# Showwork 결과 보고서의 핵심 코드 조각

## 의도

결과 보고서에서 파일을 열었을 때 긴 코드 범위 대신 실제로 중요한 짧은 부분만 보여준다. 한 파일에 중요한 부분이 떨어져 있으면 여러 조각으로 나누고, 각 조각 바로 아래에 왜 중요한지 적는다. 사용자가 고른 배치는 코드 다음에 이유가 나오는 세로형이다.

이 변경은 앞으로 만드는 Showwork 결과 보고서와 이미 게시한 Android Emulator 결과 보고서에 적용한다.

## 범위와 기준

- 파일 목록은 기존처럼 접혀 있고, 파일을 열면 해당 파일의 코드 조각 1~4개가 차례로 나온다. 각 조각에는 짧은 제목, 실제 행 번호, 구문 색상, 복사 버튼, 구체적인 이유가 있다.
- 보고서 작성자는 파일마다 동작을 설명하는 핵심 줄을 고른다. 보통 조각당 5~15행을 쓰며, 새 형식은 최대 20행으로 제한한다. 넓은 연속 범위로 무관한 코드까지 넣지 않는다.
- 읽기 화면이 자동으로 '중요한 줄'을 추측하지 않는다. 보고서를 만드는 쪽이 코드와 이유를 함께 선택하고, 게시 시 그 코드가 보고서에 저장된다. 나중에 소스 파일이 바뀌어도 게시된 설명은 그대로 남는다.
- 좁은 창에서도 조각과 설명은 세로로 쌓인다. 코드가 길면 코드 영역만 가로로 스크롤된다.
- 파일 전체를 보여주는 기존 보고서, 한 범위만 보여주는 기존 보고서, diff 보고서는 그대로 읽힌다. 기존 보고서를 일괄 변환하지 않는다.
- 코드 선택은 결과 설명의 일부다. 테스트 통과 여부와 실제 화면 캡처의 근거를 코드 조각으로 대신하지 않는다.

## 검토한 방식

1. **선택: 파일 안에 `snippets` 배열을 둔다.** 파일 이름은 한 번만 보이고, 각 코드 조각의 제목과 이유를 별도로 보관한다. 게시 단계와 화면 렌더러를 함께 바꿔야 하지만 구조가 분명하다.
2. 같은 파일을 여러 `files` 항목으로 반복한다. 기존 형식을 더 많이 재사용할 수 있지만 파일 이름이 반복되고, 한 파일의 조각을 묶은 화면을 만들기 어렵다.

## 데이터와 화면

새 보고서는 아래와 같이 원본 파일의 행 범위를 지정한다. `path`와 `why`는 파일 전체가 왜 검토 대상인지 설명한다. 각 `snippet`의 `title`과 `why`는 그 부분의 역할과 이유를 설명한다.

```json
{
  "files": [{
    "path": "app/src-tauri/src/store.rs",
    "why": "Android 세션 기록을 앱이 안전하게 읽는 부분입니다.",
    "snippets": [
      {"title": "Android 세션 종류", "lines": [216, 217], "why": "기기 번호와 연결 값을 Android 세션으로 묶습니다."},
      {"title": "잘못된 기록 거르기", "lines": [257, 263], "why": "잘못된 기기 번호나 연결 값을 앱에 보내기 전에 막습니다."}
    ]
  }]
}
```

`companion.py publish`는 같은 파일을 한 번 안전하게 읽고, 각 범위를 실제 코드와 `start_line`으로 바꿔 보고서에 저장한다. 각 조각은 1~20행이고, 파일당 1~4개다. 경로 이탈, `.git`·`.env` 파일, 바이너리, 없는 행, 빈 제목·이유, 기존 최상위 `code`/`lines`/`diff`와 `snippets`의 혼용은 거부한다. 전체 보고서 코드 크기 제한도 기존처럼 적용한다. 기존 `files` 자료 형식은 변경하지 않고 계속 지원한다.

화면은 파일 단위 접힘 목록 안에 조각별 카드가 세로로 나온다. 카드 제목에 행 범위를 보이고, 코드 바로 아래에 이유를 둔다. 코드 조각마다 복사할 수 있으며 키보드로 파일을 열고 코드 영역을 스크롤할 수 있다. 기존 코드 보기와 diff 표시는 그대로 둔다.

## 이번 Android 보고서

현재 게시된 Android 결과 보고서는 이미 코드와 화면 캡처를 스냅샷으로 보관한다. 임시 폴더의 원본 JSON을 바탕으로 중요한 파일마다 짧은 `snippets`와 이유를 다시 고른다. 검증 결과·미확인 항목·캡처 출처는 유지한다. 수정본은 `publish`로 새 결과 보고서로 게시한다. 기존 보고서는 자동 삭제하지 않아 기록이 남는다. 같은 보고서 ID를 덮어쓰는 기능은 이번 범위에 넣지 않는다.

## 전달과 확인

- 저장소의 Showwork 결과 안내와 companion 문서를 바꿔 새 보고서에서 여러 조각과 구체적인 이유를 쓰도록 한다. 사용 중인 로컬 Codex/Claude 설치본도 현재 설치 방식에 맞춰 갱신해 이후 세션에서 새 안내를 읽게 한다.
- Python 게시 테스트로 실제 코드 추출, 행 번호, 제한, 경로 안전성, 구형 보고서 호환을 확인한다. 브라우저 테스트로 여러 조각·각 이유·복사·좁은 창·구형 파일과 diff 표시를 확인한다.
- 앱을 다시 빌드하고 설치해 새 렌더러 자산이 들어갔는지 확인한다. 수정한 Android 보고서를 게시하고 렌더링된 코드 조각과 캡처·검증 항목을 눈으로 확인한다. 데스크톱 GUI 자동 조작은 사용하지 않는다.
- 코드·문서·설계 문서는 사용자가 이 작업에서 따로 요청하지 않는 한 커밋하거나 푸시하지 않는다.

## 이번에 하지 않는 일

화면에서 자동으로 중요한 코드를 추측하는 기능, 기존 모든 보고서의 일괄 수정, 오래된 Android 보고서의 자동 삭제, 전체 파일 펼치기 버튼, 결과 보고서 밖의 승인·선택 화면 변경은 포함하지 않는다.
