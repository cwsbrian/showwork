라우팅 · 요청이 어디서 갈라지는지 보기

가상 예시: 문서 조회 API에 삭제 기능을 추가했습니다. 인증·관리 권한·문서 존재 여부가 응답을 결정합니다. 실제 앱을 분석한 결과가 아닙니다.

읽는 법: 마름모는 판단, 화살표의 예/아니오는 조건, 붉은 상자는 실패 응답입니다. 이 가상 계약은 DB 행 삭제만 다룹니다. 실제 작업에서는 취소·파일 정리·예외 처리도 해당 소스에 있는 경로를 따라 표시합니다.

가상 경로전후응답실제 작성 시 채울 근거

상태 코드와 파일 위치는 대상 프로젝트에서 확인해야 합니다. 이 예시에 실제 소스 위치나 실행 증거는 없습니다.

마이그레이션 · 테이블 관계의 전후 보기

가상 예시: 문서에 선택적 폴더 관계를 추가합니다. 선은 FK 필드에서 참조하는 PK 필드로 연결됩니다. 아래 마이그레이션은 실제 작성·실행되지 않았습니다.

관계 읽기: 폴더 하나에 문서 0개 이상(0..N), 문서 하나에 폴더 0개 또는 1개(0..1). 문서 하나에 파일 행 0개 이상, 파일 행 하나는 문서 1개에 속합니다.

범례: 초록 + [추가]/[변경] = 이번 변경, 회색 + 유지 = 기존 관계. 실선은 이 예시에서 가정한 DB 외래 키입니다. 실제 FK가 없는 앱 수준 관계라면 점선과 명시적 설명을 사용합니다.

적용 상태: 설명용 가상 스키마 · 작성/로컬 적용/운영 적용 모두 해당 없음.
가상 롤백의 손실: folder_id와 folders를 제거하면 폴더 분류 정보는 사라집니다. 문서·파일 행은 유지됩니다.

보조 자료 · 컬럼 변경 및 적용 순서
대상이전 → 이후가상 배포 시 고려할 점
folders없음 → id PK, name NOT NULL문서의 FK보다 먼저 생성
documents.folder_id없음 → nullable FK, non-unique index기존 문서는 NULL, 백필 없음. 스키마 적용 후 새 코드 배포
document_files.document_id변경 없음 · NOT NULL FKON DELETE CASCADE는 파일 행에만 적용, 물리 파일 삭제를 뜻하지 않음

실제 작업에서는 마이그레이션 파일:줄, 실행 기록, DB별 잠금 영향과 롤백 명령을 확인해 채웁니다. 예시의 배포 설명은 실행 증거가 아닙니다.
